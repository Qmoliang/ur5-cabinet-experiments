两种实验回答不同问题

项目 旧online final_r17 300例 新C/A/B 900次
系统 在线观测＋认证RRT路径＋LiuQP跟踪＋安全门 冻结历史地图上的局部控制；控制阶段禁止RRT/全局路径搜索
目标信息 规划路径与航点引导 C/A仅最终目标；B额外计算静态终态假设和固定终态线证书
输入地图 按原规则在线发布、更新 从各旧案例首动前最后可用因果发布冻结；无运动案例使用最后可用的运动前发布
时间 原300秒活动时域，感知/规划/等待遵循旧协议 300秒物理仿真含控制等待；1200秒完整单次墙钟含B初始化
验收 原协议安全到达；旧字段strict_pass不可直接视为新严格指标 物理安全到达与全程QP/备份/记忆严格成功分开
结果 298/300（系统级成绩） C174/A186/B294物理安全到达；严格128/186/294

起点与目标已逐例对照旧公开回放，300组一致。但地图信息条件、规划参与、执行时序和部分验收性质不同，因此298→294不能直接解释为新控制退化4例。

需要纠正的表述

  1. 298/300不是纯LiuQP成功率。 它包含预先认证路径和跟踪。
  2. 新方法并非“完全没有轨迹计算”。 控制阶段不建RRT/搜索树，但会评估并认证当前构型到终态的固定收缩线，也使用完整终态关节方向。
  3. KKT等价不是全局到达证明。 它只说明给定条件下同状态提案的有效QP等价；保持、制动和切换另有契约。
  4. 本轮没有验证新的在线感知或实机硬实时。 900条是15任务×20输入×3组，输入曾参与开发。
  5. 不同“严格”字段需按所在版本解释。 新严格结果包含每个实际速度的原QP行及末态备份检查；原始到达、安全到达与严格成功不能混用。
  6. 全墙钟必须包含终态初始化。 不能只报告B的运动阶段；共同成功与失败长尾应分别比较。
  7. 所有失败保留。 执行器退化、新控制退化、原QP不收敛、安全余量不足和预算停止均可查看。
