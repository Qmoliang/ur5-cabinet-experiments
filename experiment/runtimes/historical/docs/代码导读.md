# 从原入口读懂这两组代码

本包是原实现的依赖提取，不是重新推导后独立重写。文件名改为明确职责；注释/格式做了机械整理。原版本中非启用的融合分支、其他场景、主动扫描实验和旧 CLI 已从交付代码中裁去。原 C++ 数学/查询库保持整份原源码，以保留原运算实现与 ABI；它是共用依赖，不是额外实验。

## 1. 入口与模块边界

`run.py` 选择且只选择一版目录，再加入 `src/common/`。两版必须在不同进程运行，避免 Python 把一版的同名代理模块缓存后给另一版使用。它加载固定参数和本地 XML，设置原 CPU 布局，调用各自的 `pipeline.run_one`。

`view.py` 是独立只读入口，默认加载两组原记录。它不导入在线流水线、不重新拟合代理、不根据当前真值重算轨迹。数据中的 source_cycle、publish_cycle 决定何时显示某代点云和证书。

## 2. 原运动学和机械臂球证书

`src/common/robot.py` 保留原 `build_robot_certificate`、`certificate_world_state`、`set_configuration` 等函数。唯一替换的模型装配接口 `build_xml` 直接返回冻结的 XML，取代包含许多历史场景分支的生成器；返回字节与原场景相同。

对于机械臂球中心 p_i(q)，保留原雅可比 J_i(q)，中心速度为 J_i qdot。末端速度雅可比及关节速度/位置限制均为原实现。

## 3. 局部感知和增量代理

`src/common/camera.py` 保留原相机采样及遮挡逻辑。`src/common/occupancy.py` 调用原 C++ 三状态体素地图。每版的 `pipeline.PerceptionWorker` 使用相同当次深度输入，在原感知/地图线程安排下完成更新。

各版的 `proxy_manager.py` 负责跨帧融合、稳定 CenterVox 代表、代理 ID 和覆盖审计；`proxy_geometry.py` 负责原矩阵外包、PCA 分组、递归细分和覆盖检查。v4.4 的自适应球覆盖代码只位于球版目录。不要将点云、CenterVox 代表、最终代理、MVT 候选和进入 QP 的代理混为同一个集合。

## 4. 几何距离和分离法向

球版使用中心距离减机械臂球半径和已认证障碍球半径/偏置。

椭球版使用原支持和分支：对于单位法向 n，原始证书间隙为

\[
c_{ij}(n)=n^T(o_j-p_i)-r_i-\sqrt{n^TQ_jn}-\sqrt{n^TU_jn}-\delta_j.
\]

`src/common/native_support.py` 和 `native/collision.cpp` 负责原法向求解与相关最近点子程序。`controller._prefetch_directional_pairs` 先求全部候选对的法向，按机器人编号和稳定代理 ID 更新热缓存，必要时保留原残差超限重试，然后调用原冗余平面删除。这里没有移植后来重建版的 lazy 边筛边算内核。

`geometry.py` 保留相应 Python 数学参考和查看器所需的支持计算。程序实走哪个分支应看调用代码，不能只看旧 summary 中的算法标签文字。

## 5. 原三状态 QP

先由原始间隙 c_ij 判三状态，再定义硬约束间隙 h_ij=c_ij−0.006。原离散安全行保留为

\[
n_{ij}^T J_i\dot q\le h_{ij}/\Delta t.
\]

NORMAL 仅保留相应硬行；NEAR 另外保留原近障法向速度惩罚；CONTACT/RECOVERY 保留原反向脱离约束。忽略与 qdot 无关的常数，目标函数为

\[
\tfrac12\|\dot q\|^2+
\tfrac{90}{2}\|J_{ee}\dot q-v_d\|^2+
\tfrac{22}{2}\sum_{(i,j)\in\mathrm{NEAR}}(n_{ij}^TJ_i\dot q)^2.
\]

`src/common/controller.py` 是两版相同的原控制器。求解器失败时的零速度是另一个数值回退分支，不要把它与几何 CONTACT/RECOVERY 状态混淆。

## 6. 加速、发布和记录

`voxel_index.py` 使用原多级 MVT，每个代理只放入选定层；按层进行 27 单元查询，使用原 float32/AVX2 AABB 判定和外扩数值保护。`online_helpers.py` 保留建表、暴力 oracle 核对及控制器装配。

各自 `pipeline.py` 保留原进程感知、发布准备线程、控制期 GC 设置、QP 热状态和周期日志。发布线程只在快照准备好后换代。完整证据仍按原流程保存，未把逐帧压缩插入发布关键路径。

## 7. 从哪开始审核

建议顺序：`configs/original.json` → `run.py` → 各版 `proxy_manager.py` → `proxy_geometry.py` → 共用 `controller.py` → `native_support.py`/`voxel_index.py` → `native/collision.cpp` → 各版 `pipeline.py`。

`docs/source_manifest.json` 给出每个提取文件对应的原文件哈希、移除定义和接口装配变更。原脚本名字中的旧协议编号是来源标识，不代表运行时仍依赖那个历史工程。基准日志中的历史 source_hashes 同样是原证据，不应为迎合新文件名而改写。
